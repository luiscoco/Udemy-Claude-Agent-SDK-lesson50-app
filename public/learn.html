Application labWhat you will learnHow to runArchitecture & workflowCode walkthrough
01

Locate the failure stage

Compare missing executable paths, failed startup, real process exits, native error results and application validation. Preserve each kind of evidence instead of treating every failure as an API outage.

02

Read the native stream

Record message type and subtype, then inspect initialization model, tools, MCP servers, skills and plugin errors. Compare a raw result with any subsequent SDK exception.

03

Capture useful diagnostics

Use the stderr callback, a temporary debugFile and actual getContextUsage summary. Redact credentials and leave raw API body logging disabled.

04

Validate structured output

Native success alone does not guarantee the structured_output field. Check presence, configure a small compatible schema and permit the native StructuredOutput tool.

05

Reproduce and fix

Six fault experiments reproduce a real SDK failure or application guard, then rerun the corrected configuration. A controlled Node CLI fixture demonstrates an actual process exit and stderr without faking a model failure.

06

Route symptoms to the right topic

Use the symptom map for skills, MCP authentication, plugins, subagents, checkpoints, hooks and hosting. Keep Python-only startup distinctions separate from this TypeScript application.
